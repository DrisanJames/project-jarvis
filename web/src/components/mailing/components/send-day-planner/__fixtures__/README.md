# Send-Day Planner — golden POST-body fixtures

Generated by:

```bash
python3 deploy_may12_mature.py --slot all --dry \
  --dump-post-body upside-down/web/src/components/mailing/components/send-day-planner/__fixtures__
```

(`--dump-post-body` implies `--dry`; will not POST.)

## Files

For each (slot, brand) pair:

- `<slot>_<brand>.post.json` — the wire-ready POST body (sans `_audit_*` fields).
  HTML content is replaced by `_html_sha256` and `_html_filename` for diffability.
- `<slot>_<brand>.html` — the post-pipeline HTML body (after `apply_full_pipeline`
  and `inject_brand_domain`).

## Used by

- `send-day-planner/payloadBuilder.test.ts` — for each fixture, asserts that
  `buildPayload(uiState)` deep-equals the JSON, with `html_content` checked by
  re-hashing the sidecar HTML file.
- `send-day-planner/payloadBuilder.invariants.test.ts` — asserts every fixture's
  `isp_plans[*].time_spans[*].source` is `"duration-calc"`.

## Refreshing the fixtures

Whenever `deploy_may12_mature.py` changes any of:

- Subject / preheader catalog
- Brand stagger or window hours
- Quota math
- Inclusion / exclusion segment IDs
- Pipeline transformations (link rewriter, footer injection)

…regenerate the fixtures with the command above and review the diff. Phase 4
contract tests treat any unintentional drift as a failure.
